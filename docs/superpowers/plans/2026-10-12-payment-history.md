# Payment History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Сохранять историю оплаченных периодов и сумм, архивировать удалённые серверы, выдавать Excel и показывать компактную карточку.

**Architecture:** Существующая SQLite получает таблицу оплат и признак архива. `Storage` управляет историей и транзакциями; `reports.py` формирует Excel из снимка данных; существующий `BotUI` управляет формами, карточками и отправкой документов.

**Tech Stack:** Python >=3.11, sqlite3, aiogram 3.31.0, одна новая зависимость openpyxl, uv, unittest.

**Spec:** `docs/superpowers/specs/2026-10-12-payment-history-design.md`.

## Global Constraints

- Даты окончания включительны; продление начинается на следующий день после прежнего окончания.
- Суммы хранятся в целых копейках. Неизвестная сумма отличается от нуля.
- Только разрешённые администраторы и личные чаты. Устаревшие действия не меняют историю.
- Миграция повторяемая, сохраняет серверы, адреса, идентификаторы и доставку.
- Архив доступен статистике, исключён из управления и напоминаний.
- Отчёты `.xlsx` формируются по запросу; локальная база не подменяет серверную.
- Изменения реализуются по этапам с RED → GREEN и полным набором unittest после каждого этапа.

## Review Focus

1. Прежняя база уже содержит адреса и версии: миграция дважды не создаёт две начальные оплаты.
2. Продление отменено или подтверждено устаревшей кнопкой: число оплат и сумма не меняются.
3. Неизвестная старая сумма и нулевая новая оплата: итог явно различает неполный учёт и бесплатный период.
4. Одинаковые названия, `=SUM(...)`, запрещённые символы и пустой архив: Excel открывается, строки не становятся формулами, вкладки уникальны.
5. Удаление во время рассылки, ошибка отправки документа и очень большая сумма: нет возвращения архива в рассылку, записи не теряются, неверный ввод отклоняется.

## Task 1: Хранение оплат, исправления и архив

**Files:** изменить `storage.py`, `tests/test_core.py`; создать `tests/test_history.py`.

**Interfaces:**

- Сохранить `Storage.add(fields) -> dict`, `update(server_id, version, fields) -> bool`, `delete(server_id, version) -> bool`, `get(server_id) -> dict | None`, `list() -> list[dict]`.
- Добавить `Storage.renew(server_id, version, ends_on, amount_kopeks) -> bool`, `payment_history(server_id) -> list[dict]`, `statistics(server_id=None) -> list[dict]`.
- `get`/`list` возвращают активные серверы с `payment_starts_on`, `amount_kopeks`, `total_paid_kopeks`, `known_payments`, `unknown_payments`. `statistics` возвращает также архив и вложенный список `payments`; неизвестный ID даёт пустой список.
- `validate_field("amount_kopeks", text) -> int` принимает рубли с точкой или запятой; `format_money(kopeks: int | None) -> str` даёт `1 500,50 ₽` или `не указано`.
- `FIELDS` остаётся списком реквизитов из `servers`; `amount_kopeks` — отдельное поле оплаты во входном `fields`. Для совместимости прежний вызов `add(fields)` без суммы создаёт неизвестную оплату, как миграция; интерфейс из Task 3 обязательно запрашивает сумму при добавлении. Ввод суммы хранение проверяет как целые копейки; отсутствие суммы при исправлении сохраняет прежнее значение.

- [ ] Написать `test_renew_appends_and_edit_does_not_append`: первоначальная оплата 01.10–19.10.2026 за 10000 копеек, продление до 19.11.2026 за 20000; история ровно из двух строк, вторая начинается 20.10, итог 30000. Исправление последней суммы до 20050 даёт 30050 и по-прежнему две строки.
- [ ] Написать `test_archive_keeps_history_and_rejects_stale_writes`: архив не возвращается из `get`/`list`; статистика и история сохранены; прежние `renew`/`update`/`delete` не меняют данные.
- [ ] Написать `test_migration_twice_keeps_one_unknown_payment_and_deliveries`, а также проверки отменённых транзакций, неверных границ периода и предельной даты 31.12.9999.

Денежный ввод и итог защищены от переполнения и потери копеек при Excel-экспорте.

## Task 2: Реальный Excel по одному и всем серверам

**Files:** создать `reports.py`, `tests/test_reports.py`; изменить `pyproject.toml`, `uv.lock`.

**Interfaces:**

- Вход: результат `Storage.statistics(server_id=None)` из Task 1.
- Выход: `build_report(servers: list[dict], *, single=False) -> bytes`. `single=True` создаёт одну вкладку; общий отчёт — «Сводка», «Удалённые» и вкладку каждого сервера.
- Формирование не меняет входные данные. Все суммы считаются из целых копеек, затем записываются числами в рублях; даты записываются как даты. Итоги — значения снимка, а не требующие расчёта формулы.

- [ ] Написать `test_single_report_contains_typed_dates_amounts_and_total`: после двух оплат из Task 1 файл читается как XLSX, содержит 20.10.2026 как начало второго периода, числовые 100 и 200 рублей, итог 300 рублей и метаданные сервера.
- [ ] Написать `test_all_report_preserves_archive_unknowns_and_safe_names`: активный и архивный сервер присутствуют по одному разу в сводке, архив виден на вкладке удалённых, история доступна для обоих. Неизвестная сумма подписана; нулевая остаётся числом. Дубли названий и текст `=SUM(1,2)` не ломают вкладки и не превращаются в формулы.
- [ ] Написать `test_empty_report_and_send_failure_do_not_change_data`: пустой отчёт открывается; создание файла не меняет базу или снимок.
- [ ] Запустить `uv run python -m unittest discover -s tests -p test_reports.py -v`; ожидается отсутствие `reports` или `build_report`.
- [ ] Добавить openpyxl через uv и реализовать генератор с выделенными заголовками, рублёвым форматом, читаемой шириной столбцов, закреплением заголовков и уникальными безопасными именами вкладок. Книга сохраняется в `BytesIO`.
- [ ] Запустить проверки отчётов и полный набор unittest. Создать демонстрационный отчёт на тестовых данных и проверить его чтением, значения, ширины, форматы и закрепление строк.

## Task 3: Формы, статистика и новая карточка

**Files:** изменить `bot.py`, `reminders.py`, `tests/helpers.py`, `tests/test_bot.py`, `tests/test_reminders.py`.

**Interfaces:**

- `BotUI.save` вызывает `Storage.renew` только для действия продления, а `Storage.update` — для исправлений.
- Добавление и продление запрашивают сумму перед подтверждением. Выбор полей переносится в подменю «Редактировать».
- Последовательность формы в `bot.py`: `FORM_FIELDS = (*FIELDS, "amount_kopeks")`. Этот список используется для ввода, проверки готовности и копирования редактируемых значений; состав колонок сервера из Task 1 не меняется.
- В `BotUI` добавить `list_statistics(message, page)` и `send_statistics(message, server_id=None)`. Создание XLSX выполняется через `asyncio.to_thread(build_report, snapshot, single=...)`; снимок читается в основном потоке до формирования книги. Отправка через `BufferedInputFile` и `message.answer_document`.
- Callback-данные: `fields:<id>:<version>` для подменю, `stats:<page>` для списка, `report:all` и `report:<id>` для скачивания. Старые корректные `edit`/`renew`/`delete` остаются защищены версией и признаком архива.
- `server_text(server, *, today=None) -> str` оформляет имя, ссылку хостера, копируемые адреса, последний оплаченный период, статус и суммы. Форматтер используется карточками, подтверждениями и напоминаниями; для черновиков допускаются рассчитанные будущие суммы.
