# Telegram-бот для напоминаний об оплате серверов

## Назначение

Два администратора ведут общий список серверов и получают напоминания об
окончании оплаченной аренды. Бот помогает вовремя продлевать серверы; он не
выполняет оплату и не обращается к API хостеров.

## Конфигурация

Рядом с приложением находится `.env`; в Git хранится только `.env.example`.
Настройки читаются при запуске. Для применения изменений бот перезапускается.

```dotenv
BOT_TOKEN=token_from_botfather
ADMIN_IDS=111111111,222222222
NOTIFY_TIME=12:00
TIMEZONE=Europe/Moscow
REMIND_DAYS=7
NOTIFY_OVERDUE=true
DATABASE_PATH=data/servers.sqlite3
PROXY_URL=
```

`ADMIN_IDS` — непустой список положительных Telegram ID через запятую;
первоначально пользователь указывает два ID. Число администраторов не
зашивается в код. Время задаётся в формате `HH:MM`, пояс — именем IANA,
срок предупреждения — целым числом от нуля. `NOTIFY_OVERDUE` принимает
`true` или `false`. Пути считаются относительно каталога приложения.
Ошибочная конфигурация останавливает запуск с понятной ошибкой без вывода токена.
`PROXY_URL` необязателен: пустой — прямое подключение, заданный HTTP или
SOCKS5 URL — все запросы бота к Telegram через этот прокси. Локально используется
`http://127.0.0.1:10808`; шаблон для сервера не содержит локального адреса.

## Доступ и интерфейс

Бот обрабатывает только личные сообщения и нажатия кнопок разрешённых
администраторов. Остальных полностью игнорирует: без сообщений и без ответа
на callback. Проверка доступа выполняется до любого обработчика.

`/start` показывает сообщение с inline-кнопками «➕ Добавить сервер»,
«✏️ Изменить сервер» и «🖥 Мои сервера». Обзор «Мои сервера» показывает сроки
оплаты/просрочку и позволяет открыть карточку. При пустом списке доступны
«Добавить сервер» и «🏠 Главное меню». Все кнопки прикреплены к сообщениям; текст и даты
администратор вводит обычными сообщениями. `/start`, `/cancel` и кнопка
«Отмена» сбрасывают текущий ввод, не меняя сохранённые данные.

Добавление последовательно запрашивает название сервера, название хостера,
сайт хостера, начало и конец оплаченного периода. Даты вводятся как
`ДД.ММ.ГГГГ`. Бот показывает итог и сохраняет запись только после
«Сохранить». Названия непустые, ограничены 100 символами; сайт — HTTP/HTTPS
URL с именем хоста, длиной до 500 символов. Бот не загружает указанный сайт.
Дата окончания не раньше начала; уже просроченный сервер добавить можно.

«Изменить сервер» показывает список с пагинацией по 10 серверов. При пустом
списке бот сообщает, что серверов нет, и предлагает добавить первый.
Карточка содержит все поля, кнопки изменения каждого поля, «Продлил»,
«Удалить» и возврат в меню. Каждое изменение требует корректного ввода и
сохраняется отдельно. Удаление всегда требует отдельного подтверждения.

## Напоминания

Рассылка выполняется ежедневно в настроенное местное время. Даты окончания
считаются включительно: в день окончания сервер ещё оплачен, на следующий
местный день — просрочен. Напоминание начинается, когда до окончания
остаётся от нуля до `REMIND_DAYS` календарных дней включительно.

При `NOTIFY_OVERDUE=true` напоминания продолжаются ежедневно после окончания.
При `false` они прекращаются после дня окончания. Уведомление содержит
название сервера, хостера, сайт, оплаченный период и количество оставшихся
дней либо дней просрочки. Кнопки «Продлил» и «🌐 Открыть хостер» (URL сайта)
есть всегда; у просроченного
сервера дополнительно появляется «Удалить» с подтверждением.

Рассылка идёт каждому администратору независимо от остальных. Успешная
доставка фиксируется в SQLite отдельно для сервера, даты окончания,
получателя и местного дня. Неудачная доставка одному не мешает другому;
временные ошибки повторяются с задержкой с учётом ограничений Telegram.
Записи успешной доставки сохраняются после перезапуска.

Если бот запущен после времени рассылки, он отправляет причитающиеся
напоминания за текущий день. За пропущенные дни отдельные сообщения не
рассылаются. Серверы, добавленные после времени рассылки, проверяются в
тот же день. Для переходов часового пояса на летнее/зимнее время действует
правило: не раньше настроенного времени и не более одного уведомления для
одного срока оплаты за местный день. Один экземпляр бота обслуживает одну базу.
Второй локальный запуск с той же базой отклоняется до обращения к Telegram;
блокировка действует только пока первый процесс жив и хранится в отдельном
служебном SQLite-файле.

## Продление, отмена и совместная работа

«Продлил» только открывает ввод новой даты, не отключая напоминания.
Новая дата должна быть позже сохранённой даты окончания и не раньше
сегодняшней даты в настроенном поясе. Только корректный ввод и подтверждение
«Сохранить» меняют сервер. Начало аренды остаётся прежним; его можно
отредактировать отдельно. Если новый срок всё ещё попадает в окно
напоминаний, сервер продолжает получать уведомления по общему правилу.

Пустой/ошибочный ввод оставляет администратора на текущем шаге; бот
объясняет ошибку. «Отмена», `/cancel`, переход в главное меню или перезапуск
удаляют только черновик. Напоминания не зависят от состояния диалога.
У каждого администратора отдельный черновик.

Сервер имеет номер версии. При сохранении, продлении или удалении бот
проверяет, что запись не изменилась с момента открытия действия. Если
другой администратор уже изменил/удалил сервер, бот сообщает об этом и
предлагает открыть актуальную карточку. Старые кнопки не могут перезаписать
новый срок или удалить уже продлённый сервер без повторного просмотра.
Изменение записи и проверка версии выполняются одной операцией SQLite.

## Реализация

Python, aiogram 3 для Telegram и long polling, python-dotenv для `.env`,
SQLite из стандартной библиотеки для хранения. Часовые пояса — `zoneinfo`
с пакетом `tzdata` для Windows. В одном процессе работают обработчики
диалогов и фоновая проверка расписания; отдельный планировщик не нужен.
Черновики хранятся в памяти; серверы и успешные доставки — на диске.

SQLite выбран вместо JSON, чтобы атомарно сохранять совместные изменения
и учёт доставки. Внешняя база данных для двух администраторов не нужна.
Ввод пользователя безопасно отображается без возможности внедрить
Telegram-разметку. Секреты и база исключаются из Git; токен не логируется.

Официальные справочники:
[aiogram](https://docs.aiogram.dev/en/latest/),
[python-dotenv](https://bbc2.github.io/python-dotenv/).

## Проверки и поставка

Автоматические проверки покрывают конфигурацию, валидацию дат и URL,
хранение и конфликт версий, запрет доступа посторонним, незавершённое
продление и отмену, границы окна напоминаний и просрочки, местное время,
перезапуск, частичную ошибку доставки и кнопки удаления.

Поставка включает приложение, `pyproject.toml`, `uv.lock`, `.env.example`, `.gitignore`,
тесты и README с установкой, запуском и резервным копированием базы.
Окружение и зависимости управляются через `uv sync`; запуск — `uv run python main.py`.
Каждый администратор должен сначала открыть личный чат с ботом и нажать
`/start`. Рабочий токен и ID пользователь заполняет локально.

## Ограничения

Бот должен быть запущен для доставки уведомлений. Нет интеграции с оплатой,
автоматического продления, веб-интерфейса и изменения настроек через Telegram.
При аварийной остановке после принятия сообщения Telegram, но до фиксации
доставки в SQLite возможен повтор сообщения; гарантировать ровно одну
доставку между Telegram и локальной базой невозможно.
